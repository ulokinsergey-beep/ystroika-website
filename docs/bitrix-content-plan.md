## Фаза 0 — восстановить источник (СЕГОДНЯ, без Figma)
1. Распаковать multipart-архив → получить SQL-дамп.
2. Из дампа выгрузить нужные таблицы: `b_iblock_element` + `b_iblock_element_property` + `b_iblock_property` (значения свойств) + `b_file` (картинки) для IBLOCK: 11 (статьи), 13 (отзывы — для сверки), 12 (FAQ), 7 (бренды), 29 (услуги), проекты, вакансии, сертификаты.
3. Инструменты: скилл `bitrix-data-extractor`, `scripts/process-catalog.mjs` как образец; написать `scripts/extract-content.mjs` (читает SQL, пишет .md/.json в коллекции).

## Фаза 1 — аудит полноты
- Сверить число элементов на IBLOCK с фактом в дампе (статьи, проекты, бренды, вакансии, сертификаты).
- Зафиксировать, какие активны (`ACTIVE='Y'`), отсечь скрытые/архив.

## Фаза 2 — извлечь в ПОЛНЫЙ суперсет (схема под любой Figma-layout)
Для каждого типа сохранять ВСЕ поля (не угаданный под макет минимум):
- `id` (bitrixId), `slug` (из CODE или транслит), `title`, `date` (ACTIVE_FROM), `sort`
- `previewText` (PREVIEW_TEXT, очищенный) + `previewImage`
- `body` — полный DETAIL_TEXT (HTML санитизировать ОДИН раз: убрать инлайн-стили/мусор, оставить семантику)
- `detailImage` + все картинки из свойств/тела (скачать локально в `public/images/<type>/<slug>/`)
- `category`/`tags`/`section`, `brand` (где есть)
- SEO: `metaTitle`, `metaDescription` (свойства или из заголовка)
Расширить схемы коллекций в `src/content/config.ts` под суперсет (опциональные поля).
**Картинки:** пути Битрикса (`/upload/...`) → скачать из `b_file`/архива, перелинковать на локальные.

## Фаза 3 — маппинг к Figma (ЗАВТРА, когда сброшен лимит Figma)
Для каждой инфо-страницы (блог, новости, отзывы, проекты, вакансии, сертификаты, FAQ, спец-условия, +детали):
1. Прочитать Figma-фрейм страницы (`get_screenshot`/`get_design_context`).
2. Разложить УЖЕ извлечённые поля по макету (карточки/списки/детали).
3. Посекционная сверка по `figma-quality-rules.md`.
Переэкстракции нет — все поля уже есть из Фазы 2.

## Риски и решения
- **Источник SQL не на руках** → восстановить из архива (Фаза 0) — критический первый шаг, без него extract не запустить.
- **Грязный HTML из Битрикса** → санитизация при извлечении (один раз), не на этапе вёрстки.
- **Битые/локальные пути картинок** → скачать и перелинковать в Фазе 2, чтобы вёрстка ссылалась на готовые ассеты.
- **Блог vs Новости** — в Битрикс могут быть в одном IBLOCK 11 с разными секциями; разделить по секции при извлечении.

## Что можно сделать СЕГОДНЯ (без Figma)
Фазы 0–2 целиком: восстановить дамп, извлечь полный суперсет, скачать картинки, расширить схемы. К завтрашней вёрстке данные будут готовы — останется только маппинг к макету.
