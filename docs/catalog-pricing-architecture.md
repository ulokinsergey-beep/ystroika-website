# Архитектура каталога и цен: мульти-поставщик (v2, design-freeze)

> Управляемый продуктовый контур, а не «получили цены». Поставщики (Döcke,
> КровАльянс, в будущем Bitrix/Directus) → нормализация → маппинг → правила цены
> → версионный снимок → сайт. **API поставщика ≠ структура сайта.**
> Принцип: поставщики питают только цену; SEO/AEO/карточки зависят от мастера.
> Связано: `skills-architecture.md` §7.1, `07-schema-org.md` §0, `fact-checking.md`.

---

## 1. Решения владельца (зафиксировано)

| Вопрос | Решение |
|---|---|
| Источник номенклатуры | Гибрид по категориям (импорт где удобно, ведём сами где нужен контроль) |
| Правило цены | Ручная цена / наценка над базой поставщика |
| Где данные | Лёгкая БД/CMS (Directus) — **позже**, как админка над рабочим ядром |
| Обновление | n8n: cron + кнопка — **позже** |
| Остатки | НЕ тянем. Поле `availability: "unknown"`, на сайте «наличие уточняйте» |
| Старт | Ядро на data-файлах **без Directus** (Фаза 2A) |

## 2. Конвейер и структура (normalized layer)

```
Поставщик (сырьё) → Adapter → Normalizer → Mapping → Pricing rules → Snapshot → Astro
```

```
src/catalog/
  adapters/        docke.ts · krovalians.ts        // достать сырьё из API (auth, fetch)
  normalizers/     normalizeDockeProduct.ts · normalizeKrovaliansProduct.ts
  mapping/         product-supplier-map.json       // productId ↔ поставщики
  pricing/         pricing-rules.json              // наценки/приоритет/округление
  snapshots/       price-snapshot-latest.json      // что читает сайт
                   price-snapshot-<ISO>.json       // версии
                   product-snapshot.json
                   price-snapshot-report.json      // отчёт генерации
```

Правило слоёв: сначала **нормализуем**, потом **маппим**, потом **считаем цену**, потом отдаём сайту. Сайт читает только snapshot.

## 3. Контракты данных

### 3.1. Нормализованный товар поставщика (выход адаптера+нормализатора)
```json
{ "source": "docke", "supplierSku": "ST19737", "vendorCode": "GL-KAMEA-8017",
  "brand": "Döcke Pie", "name": "Гибкая черепица Döcke PIE СОТА Зелёный",
  "category": "gibkaya-cherepitsa", "basePrice": 330, "currency": "RUB",
  "unit": "796", "updatedAt": "2026-06-10T12:00:00+03:00", "raw": { } }
```
`raw` — исходный объект поставщика (для отладки, на сайт не идёт).

### 3.2. Master product id (внутренний ID товара сайта) ⭐
Самая большая проблема — не цена, а **сопоставление товаров** (разные артикулы/SKU/vendor/названия/цвета/упаковки у источников). Поэтому у каждого товара сайта — стабильный `productId`:
```json
{ "productId": "metallocherepica-grand-line-kamea-ral-8017",
  "brand": "Grand Line", "category": "metallocherepica" }
```
`productId` — slug-like, стабильный, на нём держатся URL/карточка/SEO. Никогда не равен SKU поставщика.

### 3.3. Маппинг (mapping/product-supplier-map.json)
```json
{ "productId": "...kamea-ral-8017",
  "links": [ { "source": "docke", "supplierSku": "ST19737", "priority": 1, "active": true },
             { "source": "krovalians", "supplierSku": "00-134456", "priority": 2, "active": true } ] }
```
Без маппинга — хаос (цена одного товара подтянулась к другому). **Несопоставленный товар в публичный snapshot НЕ идёт.**

## 4. Правила приоритета источников (pricing/pricing-rules.json)

```json
{ "defaultPriority": ["krovalians", "docke"],
  "byBrand": { "Döcke": ["docke", "krovalians"], "Döcke Pie": ["docke"],
               "Grand Line": ["krovalians"] } }
```

**Зафиксированные правила:**
1. Бренды Döcke → основной источник **Döcke API**.
2. Остальные бренды → основной источник **КровАльянс**.
3. Нет цены → «**по запросу**» (без Offer).
4. Порог скачка цены (авто-стоп) — **отключён** по решению владельца. (Каркас оставлен, легко включить позже.)
5. Товар не сопоставлен → **не отдаём в публичный snapshot**.

---

## 5. Правила цены (pricing-rules.json)

**Текущая модель (решение владельца): цена продажи = РРЦ поставщика, округление до 10 ₽ вверх.** Не наценка над базой.

```json
{ "priceMode": "rrp",
  "priceSource": { "docke": "rrp", "krovalians": "retail" },
  "rounding": { "step": 10, "mode": "up" },
  "overrides": { "productId-X": { "mode": "manual", "price": 1990 } } }
```
`sellingPrice` = РРЦ источника → округление вверх до 10 ₽; либо ручной `override`.
Каркас процентной наценки (по категории/бренду) оставлен на будущее — **сейчас выключен**.

- **Döcke РРЦ:** `POST /api/client/prices/rrp/get` → плоский `{vendor, measure, price}` (~4193 позиции, проверено 2026-06-10).
- **КровАльянс розница:** уточнить поле (`price` / `discounted_price` / отдельная РРЦ) при сборке адаптера.

## 6. Защита от кривых цен (перед публикацией snapshot)

Каждая позиция проходит проверки, иначе не публикуется (→ warning/blocker в отчёт):
- `price > 0`; валюта `RUB`;
- дата обновления свежая;
- (порог скачка цены — отключён по решению владельца; каркас сравнения с прошлым latest оставлен на будущее);
- товар **сопоставлен** (есть productId);
- источник цены понятен;
- правило наценки применилось;
- (если запрещено) итоговая цена не ниже закупочной.

Одна ошибка API не должна выкатить нули/мусор на сайт.

## 7. Версионность снимка + отчёт

```
snapshots/
  price-snapshot-latest.json              // читает сайт
  price-snapshot-2026-06-10T12-00-00.json // история (откат)
  price-snapshot-report.json              // отчёт генерации
```
`report.json`:
```json
{ "generatedAt": "2026-06-10T12:00:00+03:00",
  "sources": { "docke": {"products":18800,"prices":4035,"mapped":3900,"unmapped":135},
               "krovalians": {"products":12000,"mapped":11000} },
  "warnings": [], "blockers": [] }
```
Правило обновления: новый latest пишется **только если нет blocker'ов**; иначе старый latest сохраняется.

## 8. Подключение к сайту (Фаза 2B)

1. Astro читает `price-snapshot-latest.json` (build-time / кэш).
2. Листинг/карточка: цена если валидна; иначе «**по запросу**».
3. **Product/Offer JSON-LD — только где цена реальная** (07 §0). Нет цены → без Offer.
4. **`availability: "unknown"`** — остатки не тянем, `InStock` НЕ ставим. На сайте «наличие уточняйте».
5. CTA: цена есть → «Уточнить наличие»; цены нет → «Узнать цену и наличие».

---

## 9. Как защищены SEO / AEO / карточки
URL = `productId` (никогда SKU поставщика). title/description/JSON-LD/тексты = поля мастера + `sellingPrice`. Смена поставщика/наценки/перепривязка меняет **только поле цены** — идентичность, URL и разметка стабильны.

## 10. Секреты (важно)
- **Продакшн:** реальные доступы — из **env / секретов хостинга / CI / Docker secrets**. Адаптеры читают `process.env`, не файл.
- **`credentials.md`** — только **локальная памятка** (gitignored), не способ хранения боевых доступов.
- Секреты не в репозитории, не в snapshot, не в `raw`, не в логах.

## 11. Фазы

**2A — ядро данных (без Directus):**
1. Адаптеры `docke.ts`, `krovalians.ts` → сырьё.
2. Нормализаторы → контракт §3.1 (source, supplierSku, vendorCode, brand, name, category, basePrice, currency, updatedAt, raw).
3. Маппинг §3.3 (productId, source, sku, priority, active).
4. Pricing rules §4–5.
5. Генератор snapshot: цены → маппинг → наценка → проверки §6 → `price-snapshot-latest` + версия + report.

**2B — подключение к сайту:** §8 (snapshot → листинг/карточка/JSON-LD/CTA).

**2C — Directus (позже):** админка над рабочим ядром — маппинг, наценки, ручные override, скрытие товаров, приоритет, логи, ручной запуск. Управляет правилами, **не сердце системы**.

**2D — n8n (позже):** ночное обновление; blocker → уведомление; скачок цены → на проверку; API упал → **не затирать старый snapshot**; успех → обновить latest.

## 12. Роли поставщиков (избегаем дыр в ассортименте)
- **Döcke** — специализированный: гибкая черепица, сайдинг, водосток, фасад **бренда Döcke** (~18 800 SKU, прайс 4035, ключ `vendor`).
- **КровАльянс** — широкий каталог (остальные бренды).
- Döcke ≠ универсальный источник каталога; маппинг и приоритет учитывают это.

---

## 13. Идеальная формула
```
Поставщик даёт сырые данные → Adapter приводит к единому формату →
Mapping связывает с товарами сайта → Pricing rules считают публичную цену →
Snapshot фиксирует стабильную версию → Astro читает быстро и безопасно →
Directus потом управляет mapping/rules → n8n потом автоматизирует обновления.
```

## 14. Решения по цене (зафиксировано 2026-06-10)
- **Цена продажи = РРЦ поставщика, округление до 10 ₽ вверх.** Без процентной наценки.
- **Порог скачка цены — отключён** (авто-стопа публикации нет). Каркас оставлен на будущее.
- Döcke РРЦ — endpoint `/api/client/prices/rrp/get`. КровАльянс — поле розницы уточнить при сборке адаптера.
