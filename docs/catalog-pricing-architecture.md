# Архитектура каталога и цен: мульти-поставщик (КровАльянс / Döcke / Grand Line)

> Design-freeze. Решения владельца зафиксированы (см. §1). Принцип: **сайт продаёт
> свои товары, а не товары поставщиков** — канонический каталог стабилен, поставщики
> питают только цену. Это защищает карточки, SEO, AEO от смены поставщиков.
> Связано с `skills-architecture.md` §7.1 (владение ценой) и `07-schema-org.md` §0.

---

## 1. Зафиксированные решения владельца

| Вопрос | Решение |
|---|---|
| Источник номенклатуры | **Гибрид по категориям**: где у поставщика хорошие данные — импорт; где нужен контроль — ведём сами |
| Правило цены | **Ручной режим / наценка**: база от поставщика, финальная цена продажи задаётся нами (наценка/округление/ручная) |
| Где данные | **Лёгкая БД / CMS** (с админкой) под товары + маппинг + цены |
| Обновление | **n8n: cron раз в неделю + ручная кнопка** «прайс поменялся» |
| Остатки | НЕ тянем и НЕ показываем. На сайте: товар + цена (или «по запросу») |

## 2. Четыре слоя

```
┌─ КАНОНИЧЕСКИЙ КАТАЛОГ (мастер) ──────────────┐   ← карточки, SEO, AEO, URL зависят ТОЛЬКО отсюда
│  Product: id, slug, title, category, attrs,  │
│  images, seo{title,desc}, description,       │
│  pricing{mode, markup, manualPrice,          │
│           sellingPrice, currency, updatedAt} │
└──────────────────────────────────────────────┘
        ▲ маппинг (1 товар → 1..N поставщиков)
┌─ SUPPLIER LINK ──────────────────────────────┐
│  productId, supplier, supplierSku,           │
│  basePrice, priority, lastSyncedAt           │
└──────────────────────────────────────────────┘
        ▲ нормализация {sku, basePrice}
┌─ АДАПТЕРЫ ПОСТАВЩИКОВ ────────────────────────┐
│  КровАльянс · Döcke · Grand Line (изолированы)│
└──────────────────────────────────────────────┘
```

**Категория** хранит режим: `sourceMode = import:{supplier} | curated` (гибрид §1).

---

## 3. Стек (рекомендация)

- **Канонический store + админка:** headless-CMS **Directus** (self-host на Timeweb, Postgres внутри).
  Даёт удобную админку для управления товарами/маппингом/наценкой без кода (важно для владельца),
  REST/GraphQL для сайта и n8n. Альтернатива — чистый Postgres + минимальная админка.
- **Оркестратор синхронизации:** **n8n** (уже в стеке) — cron еженедельно + webhook-кнопка.
- **Сайт:** Astro читает **снимок каталога+цен** (build-time), n8n триггерит пересборку после
  обновления цен. Страницы быстрые, стабильные, SEO-дружелюбные; полностью отвязаны от API поставщиков.
- **Секреты** API поставщиков — только в `credentials.md` / env, не в репозитории.

## 4. Расчёт цены продажи (ручной режим / наценка)

```
basePrice  = цена приоритетного поставщика из SupplierLink (или по правилу)
sellingPrice =
  mode = manual         → manualPrice
  mode = markup_percent → basePrice * (1 + markup/100)
  mode = markup_fixed   → basePrice + markup
  + округление по правилу
Если basePrice нет и нет manualPrice → «цена по запросу», Offer НЕ ставится (07 §0).
```
Наценку можно задавать глобально, по категории или на товар (переопределение).

---

## 5. Синхронизация (n8n)

```
Триггер: cron (раз в неделю) ИЛИ webhook-кнопка «прайс поменялся»
 → для каждого поставщика: адаптер тянет цены по привязанным SKU (НЕ остатки)
 → пишет basePrice в SupplierLink (+ lastSyncedAt)
 → пересчитывает sellingPrice в Product
 → триггерит пересборку сайта (снимок обновлён)
 → лог: что обновилось, что не нашлось (warning)
```
Импорт номенклатуры (для import-категорий) — отдельный поток n8n: создаёт/обновляет Product
из API поставщика, дальше товар курируется в Directus.

---

## 6. Как это защищает SEO / AEO / карточки

- **URL** = канонический slug, никогда не SKU поставщика.
- **title/description/JSON-LD/тексты** = поля мастера + `sellingPrice`.
- **Offer.price** = `sellingPrice`; нет цены → Offer не выводится (без ложной цены).
- Смена поставщика, новый поставщик, перепривязка, изменение наценки → меняется **только поле цены**.
  Идентичность товара, URL и вся SEO/AEO-разметка **не трогаются**. Это и есть цель владельца.

## 8. Что нужно от владельца для старта (Фаза 1)

1. **Хост канонического store:** Directus на Timeweb (рекомендую) — или другой вариант.
2. **API-доступы** Döcke и Grand Line (endpoint, ключ, формат) → в `credentials.md`. КровАльянс уже есть.
3. **Категории-импорт vs курируемые:** по каким разделам берём номенклатуру из API, по каким ведём сами.
4. **Базовая наценка:** процент/правило по умолчанию (можно потом переопределять per-категория/товар).

## 9. Влияние на текущий код

- Сейчас листинг тянет цену живьём (`/api/catalog/prices`, CSR) и наличие (`/api/catalog/stock`).
  Новая модель: **снимок цен** из мастера; `stock` убирается (остатки не показываем).
- Скил `product-catalog-api` (КровАльянс-only CSR) — обновить под канонический мульти-поставщик
  снимок (источник цены = мастер, не прямой API).
- Карточка/листинг 1-в-1 Figma **не меняются** — только источник поля цены.
