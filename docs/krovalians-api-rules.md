## 1. Подключение

- **Базовый URL:** `https://b2b.krovalians.ru:8080/kroval/hs/api`
  - Порт **8080**, **HTTPS**, нужен **legacy TLS renegotiation** (в Node — `undici Agent {connect:{rejectUnauthorized:false}}`; в Python — `ssl.OP_LEGACY_SERVER_CONNECT`).
  - В инструкции адрес без порта/схемы — порт 8080 подтвердил менеджер (актуально).
- **Параметры доступа** (запрашиваются у менеджера КА): имя пользователя, пароль, ключ доступа `API_Key`, **уникальный идентификатор соглашения `soglashenie`**.
  - Текущие (2026-06-11): логин `УлокинСЮ`, пароль и `API_Key` — в `credentials.md`/`.env`. `soglashenie` — в `.env` (`KROVAL_SOGLASHENIE`).

## 2. Заголовки (обязательны во ВСЕХ запросах)

```
Content-Type:  application/json; charset=UTF-8
API_Key:       <ключ>          ← имя заголовка строго в таком регистре: API_Key
API_Version:   1.1
Authorization: Basic <base64(UTF-8: "логин:пароль")>
```

⚠️ **Регистр имени `API_Key` важен.** Клиенты, которые приводят имена заголовков к нижнему регистру (напр. Python `urllib` → `Api_key`), получают **401**. Node `fetch`/`http.client` шлют как задано — работает. (Это и есть «проверьте заголовок» от менеджера.)

## 3. Метод HTTP
Все три метода — **POST** с JSON-телом (в 1С это `ОтправитьДляОбработки`). Путь = базовый URL + `/{метод}`.

## 4. Методы (в инструкции их ровно ТРИ)

### 4.1. `/katalog` — полный справочник номенклатуры
- **Тело:** `{"katalog": "full"}`
- **Ответ:** `{"КаталогНоменклатуры": [ {…поля товара…} ]}`
- **Поля товара:** `UID`, `UID_Roditel`, `ЭтоГруппа` (true=папка/группа, false=товар), `Артикул`, `Наименование`, `ЕдиницаИзмерения`, `Код` (= КодКровАльянс, ключ для цен/остатков), `КодРодителя`, `Производитель` (бренд), `ЦеноваяГруппа`, `Марка`, блоки **Вес/Длина/Объём/Площадь** (`*Использовать`, `*ЕдиницаИзмерения`, `*Числитель`, `*Знаменатель`), `Упаковки[]`.
- Объём большой (~200 МБ) — читать потоково/частями.

### 4.2. `/price` — цены номенклатуры
- **Тело:** `{"nomenclatures": [<коды>], "soglashenie": "<uuid>"}`
  - `nomenclatures` — массив **Код**ов (НЕ `kods`!), **не более 150** за запрос → бить на пачки по 150.
  - `soglashenie` — **обязателен**.
- **Ответ:** `{"prices": [ {"kod", "price", "discounted_price", "UID"} ]}`
  - `price` — базовая цена; `discounted_price` — цена клиента со скидкой.
  - Возвращаются ТОЛЬКО товары, у которых есть цена под соглашением; остальные коды в ответ не попадают (это норма, не ошибка).

### 4.3. `/exchange` — текущие остатки (метод `remaining_goods`)
- **Тело:** `{"nomenclatures": [<коды>]}`
- **Ответ:** `{"КодыИОстатки": { "<код>": <остаток>, … }}`
- **На сайте остатки НЕ используем** (решение владельца, `catalog-pricing-architecture.md`). Метод доступен, если понадобится.

## 5. Ошибки
- **401** — авторизация не пройдена: проверить логин/пароль/`API_Key` (и регистр заголовка `API_Key`).
- Пустой `prices: []` при 200 — НЕ ошибка доступа: значит у этих кодов нет цены под соглашением **или** коды устарели/не существуют в живой базе.

## 6. ⚠️ Правило тестирования (наученное на ошибке 2026-06-11)
**Проверять только на ЖИВЫХ кодах из текущего `/katalog`.** Коды из старых локальных выгрузок (`src/data/catalog/*.json`) могут не существовать в живой базе → пустой ответ цен вводит в заблуждение. Сначала взять код из свежего `/katalog`, потом им проверять `/price`.

## 7. Что отдаёт КА, что нет
- **Отдаёт:** номенклатуру (с весом/длиной/объёмом/площадью/упаковками/производителем), **цены** (базовая + со скидкой), **остатки**.
- **НЕ отдаёт:** картинки товаров, текстовые описания, расширенные характеристики (в отличие от Döcke). Картинки/описания по пересекающимся товарам можно брать у Döcke/Grand Line.
