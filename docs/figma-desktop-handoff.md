Скрипт сам делает MCP-handshake к `http://127.0.0.1:3845/mcp`, парсит SSE,

нужный файл активен.

Доступные инструменты сервера: `get_design_context`, `get_variable_defs`,
`get_screenshot`, `get_metadata`, `get_figjam`.

## Главное правило вёрстки

**Сайт делаем 100% 1-в-1 с Figma. Не «похоже», а точно.**

- Визуал / размеры / цвета / отступы / типографика / расположение / состояния — ровно как в макете.
- Ничего не выдумывать и не «улучшать» без явного согласия владельца.
- **Разграничение:** визуал = 1-в-1 с Figma; контент (тексты, цены, товары) = из реальных
  источников (Bitrix / КровАльянс API), тоже не выдуманный.
- **Проверка обязательна перед «готово»:** `get_screenshot` (эталон Figma) ↔ скриншот сайта
  ↔ `preview_inspect` (точные значения).
- **Урок (важно!):** проверять только габариты контейнеров — НЕДОСТАТОЧНО. Это даёт ложную
  уверенность. Нужна **визуальная** сверка скриншота Figma и скриншота/вида сайта по каждому экрану.

## Как читать дизайн (инструменты MCP)

Сервер figma-desktop (в settings.json) даёт инструменты с параметрами `fileKey` + `nodeId`:

- `get_metadata(fileKey, nodeId)` — структура узла (id, типы, размеры, позиции). Большой вывод сохраняется в файл.
- `get_design_context(fileKey, nodeId)` — референс-код + **URL ассетов** (картинки/иконки).
  Скачивание ассета: `curl -o public/images/<name>.png "<asset_url>"` (URL живёт ~7 дней).
- `get_screenshot(fileKey, nodeId, maxDimension)` — **эталонная картинка экрана** (без токена).
  Возвращает короткоживущий URL → `curl -o ref.png "<url>"` → смотреть.

Также есть инструменты по «текущему выделению» в Figma (читают выделенный фрейм) — менее надёжны, требуют выделения + перезапуска.
