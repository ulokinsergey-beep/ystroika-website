# Правила качества вёрстки 1-в-1 (свод по разбору «косяков» владельца)

> Живой документ. Соблюдать на ВСЕХ страницах (услуги, каталог, карточка, инфо).
> Контекст: владелец проверил лендинг услуги и нашёл серию косяков. Вывод владельца —
> «это больше 50% от того, что нужно для качества». Значит проблема СИСТЕМНАЯ (процесс),
> а не отдельные заплатки. Этот документ + протокол ниже — обязательны к исполнению.

---

## Главный вывод (почему было плохо)

1. Одношаговая сборка «агент сверстал всё за раз» + оптимистичная самооценка («92-95%») —
   **НЕ заменяет посекционную визуальную сверку с Figma**. Самооценку агента не принимать на веру.
2. Заглушки и захардкоженный повторяющийся контент выдаются за готовое — это и есть «косяки».
3. Проверяли числа/габариты, но не сам ВИД секции против эталона Figma.

---

## Правило 1 — фон-фото с overlay: ключевой объект не перекрывать
Если поверх фото лежит карточка/текст — смысловой центр фото (человек, действие) НЕ должен быть
под оверлеем. Сверять кадр/ориентацию с Figma; при необходимости зеркалить (`-scale-x-100`) или
смещать фокус (`object-position`). *(косяк: монтажник Hero был спрятан под тёмной карточкой)*

## Правило 2 — пропорции колонок: flex по соотношению, НЕ фикс-px
Ряды «текст+фото»/колонки разной ширины — `lg:flex-[A_1_0%]` / `lg:flex-[B_1_0%]` по соотношению
Figma + высота фото через `aspect-[W/H]`, НЕ `w-[Npx]`/`height:Npx`. Выравнивание как в Figma
(чаще `items-start`). Проверять на 1920 И 1440 — доли и аспект держатся. *(косяк: «Основа» на 1440 ломалась)*

## Правило 3 — НИКАКОГО повторяющегося/заглушечного контента
Каждая карточка/строка/блок получает СВОЙ реальный контент, а не один и тот же текст,
скопированный N раз. Источник — реальные данные (коллекция услуг/товаров, .md, API), как в Figma.
Если контент ещё не готов — это НЕ «готово», а явный TODO. *(косяк: 6 карточек услуг с
идентичным «Профессиональный монтаж… с гарантией качества»)*

## Правило 4 — данные и форматирование: без дублей и одинаковых значений
- Не добавлять префикс, который уже есть в данных (двойное «от от 300 руб/м2»). Проверять
  итоговую строку на дубли.
- Не показывать ОДНО значение во всех строках там, где в Figma значения разные (цены по работам).
  Одинаковая цена во всех строках = заглушка, не готово. *(косяк: вся таблица «Стоимость» = «от 300 руб/м2»)*

## Правило 5 — декоративные элементы (большие ₽ / % / фигуры): строго по Figma
Размер, позиция, **прозрачность**, z-index и обрезка (`overflow-hidden`) — ровно как в макете.
Декор НЕ должен лезть на фото/текст и быть полноцветным, если в Figma он бледный/за контентом
(часто 8-12% opacity или под слоем). *(косяк: ₽ 200px полной непрозрачности налез на фото
«Что влияет на стоимость»; рядом «%» сделан правильно — 10% opacity)*

## Правило 6 — процесс проверки (обязателен перед «готово»)
1. **Посекционная визуальная сверка:** `get_screenshot` секции из Figma ↔ скриншот той же секции
   сайта. Глядеть глазами, не только числа. Это НЕ опционально.
2. Не верить самооценке одношаговой сборки. Каждая секция проходит сверку отдельно.
3. Проверять на 1920 И 1440 (пропорции/аспекты).
4. Кэш: после правок проверять ОТДАННЫЙ сервером HTML (`curl | grep`) и помнить про жёсткий
   рефреш браузера (Ctrl+F5) — «не вижу изменений» часто = кэш, но это надо доказать grep'ом.

## Улучшенный протокол сборки страницы 1-в-1 (авто-апгрейд промта)

Использовать как чек-лист/промт при любой сборке страницы по Figma:

```
ЦЕЛЬ: страница 100% 1-в-1 с Figma (визуал + реальный контент). «Похоже» = не принято.

1. ИНВЕНТАРЬ: get_metadata корневого фрейма → список ВСЕХ секций с node-ID и порядком.
2. ПО КАЖДОЙ СЕКЦИИ (по очереди, не скопом):
   a. get_screenshot секции (эталон) + get_design_context (точные размеры/цвета/тексты/ассеты).
   b. Свёрстать по ТОЧНЫМ значениям. Пропорции — flex-[A_1_0%], аспекты — aspect-[W/H] (Правило 2).
   c. Контент — РЕАЛЬНЫЙ и УНИКАЛЬНЫЙ из данных, без повторов/заглушек (Правило 3, 4).
   d. Декор/оверлеи — по Figma: позиция/opacity/z, не перекрывать смысл (Правило 1, 5).
   e. Ассеты — скачать реальные из Figma (get_design_context → curl), не подставлять «похожие».
   f. ПРОВЕРКА: скрин секции сайта ↔ эталон Figma (глазами) + замер на 1920 и 1440. Не совпало → чинить.
3. НЕ объявлять «готово», пока КАЖДАЯ секция не прошла визуальную сверку. Перечислить честно,
   что осталось заглушкой/блокером (данные/доступы), а не выдавать за готовое.
4. После правок — проверить отданный HTML (curl|grep), напомнить про Ctrl+F5.
```

## Чек-лист перед «готово» по секции
1. Числа (ширины/высоты/отступы/цвета) = `get_metadata`/`get_design_context`.
2. **Скриншот секции сайта ≈ эталон Figma (глазами).**
3. Контент реальный и уникальный (Правило 3, 4) — нет повторов/заглушек/дублей-префиксов.
4. Декор не перекрывает контент, opacity/позиция как в Figma (Правило 5).
5. Проверено на 1920 и 1440 (Правило 2).
6. Фото-объекты не под оверлеем (Правило 1).
